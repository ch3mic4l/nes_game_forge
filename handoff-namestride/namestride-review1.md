# Findings

- **[P2] Exercise the capacity guard through `battleTables`, not only through the exported helper** — `test/unit/bankedbytes.test.js:215`. The brief requires proving that a 22-entry `BATTLE_STRINGS` list makes `battleTables` throw, but this test calls `checkBattleStringsCapacity` directly for all three assertions. Removing or forgetting the `checkBattleStringsCapacity()` call at `main/build/battletables.js:98` would therefore leave the entire test suite green while real builds once again emit an overlong `bs_text` table and `push_battle_string` wraps at the 22nd string. Drive the over-limit case through `battleTables` (for example by temporarily extending the mutable exported `BATTLE_STRINGS` array with cleanup in `finally`, or by giving the emitter an injectable list used by both the guard and emission).

- **[P2] Make a low-index control cross a page relative to the table base** — `test/unit/rpg.test.js:2289` and `test/unit/rpg.test.js:2372`. Both high-index fixtures use id 26, whose 16-bit product is `$0104`; in these builds `LOW(mon_name)` and `LOW(item_name)` are low enough that adding `$04` does not carry. An implementation that correctly computes the high byte of `index * NAME_LEN` but adds the low byte to `ptr_lo` without carrying into `ptr_hi` would pass both high-index assertions and the current actor-3/item-0 controls, yet draw the wrong entry whenever `LOW(table) + LOW(index * NAME_LEN) >= 256`. Use one of the required <=25 controls at an index that forces that base-page carry (rather than 3 and 0), so the tests cover the full 16-bit address addition rather than only the stride's high byte.
