# Findings

- **Hunk 2, “The parameter is why `checkBattleStringsCapacity` ... exists at all”** — The causality is backwards. `checkBattleStringsCapacity` exists because `push_battle_string` retained its unsafe 8-bit `index * MSG_COLS` stride and therefore needs a generator-side bound; the optional `battleStrings` parameter was added later so tests could inject a list through `battleTables`, then threaded through `battleTableBytes` so the counter measured that same injected emission. Minimal correction: replace “The parameter is why ... exists at all” with “Separately, `checkBattleStringsCapacity` ...” (or say the parameter is what lets the guard be tested through the emitter, not what caused the guard to exist).

- **Hunk 3, “offset 4 — four glyphs into the entry before it”** — An 8-bit offset of 4 is `table + 4`, four glyphs into entry 0, not four glyphs into entry 25 immediately before the requested entry 26. The old ten-glyph read therefore returned the last six glyphs of entry 0 followed by the first four of entry 1, exactly as the emulator-test diagnostics describe. Minimal correction: change “the entry before it” to “the table's first entry” (or explicitly say “entry 0”).
